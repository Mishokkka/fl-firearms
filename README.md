# FL Firearms

Модуль огнестрельного оружия 18–19 века для Foundry VTT 13.351 и Forbidden Lands 13.0.5.

## Возможности

- обычный и артефактный огнестрел;
- Камора `d12`, Капризная Камора `d6`;
- обычная скрытая осечка `d20`, Капризное `d10`;
- осечка после проваленного Push;
- модификаторы таблицы: Надежное, Утолщенное, Истонченное, Рисковое;
- магазин, полный заряд и Дозарядка;
- блокировка атаки с пустым магазином;
- ApplicationV2-диагностика мира;
- публичный API и hooks для других модулей.

## Установка

Скопировать каталог `fl-firearms` в `Data/modules/`, перезапустить Foundry и включить модуль в мире Forbidden Lands.

## Обязательные мировые данные

По умолчанию модуль ищет:

- RollTable `Пороховая осечка`;
- RollTable `Пороховая осечка - особое`;
- JournalEntry `Rich Info Tooltips` с отдельными страницами, названными точно как свойства оружия;
- Playlist `CritBad`.

Имена таблиц и плейлиста можно изменить в настройках. Журнал всегда называется `Rich Info Tooltips`; без него пропадают описания в tooltip, но механика свойств работает. Таблицы осечки должны покрывать все значения 1–6. Осечка использует числовой результат повторно независимо от `drawn`, а не расходует строки как колоду. Отсутствующая таблица или разрыв диапазонов дают явную ошибку.

После включения откройте:

`Configure Settings → Module Settings → FL Firearms: диагностика`.

## Настройка Item

Откройте дальнобойное оружие и включите `Огнестрел` в системной строке Features. Под основными характеристиками появится встроенная строка типа, перезарядки и БП, а ниже — чипы свойств.

## API

```js
const api = game.modules.get("fl-firearms").api;
```

Доступны:

```js
api.isFirearm(item);
api.getFirearmData(item);
api.getMisfireProfile(item);
api.getMagazineProfile(item);
api.getArmorPiercingProfile(item);
await api.spendMagazineAmmo(item, 2, { reason: "rapid" });
await api.loadMagazine(actor, item);
await api.topOffMagazine(actor, item);
await api.openFirearmConfig(item);
api.runDiagnostics();
```

## Hooks

```js
Hooks.on("fl-firearms.preAttack", (actor, item, context) => {});
Hooks.on("fl-firearms.attackFired", (actor, item, context) => {});
Hooks.on("fl-firearms.dryFire", (actor, item, context) => {});
Hooks.on("fl-firearms.misfire", (actor, item, result) => {});
Hooks.on("fl-firearms.magazineChanged", (actor, item, oldValue, newValue, context) => {});
```

Возврат `false` из `fl-firearms.preAttack` отменяет вызов системного roll-метода.

## Сетевая работа

Изменения магазинов, их емкости и общего ресурса проходят через очередь на Actor UUID. Исполнитель — активный GM с наименьшим ID, а при отсутствии GM — активный владелец с наименьшим ID. Это координация записи для дружеского стола, без дополнительного слоя защиты от читерства.

Для собственных действий исполнитель использует прямой вызов; остальные клиенты отправляют команду через штатный сокет Foundry. Повторная доставка того же запроса не повторяет действие. При тайм-ауте нет автоматического повтора или локального fallback: команда могла уже сохраниться. Уведомление предлагает проверить магазин перед повтором. После обновления модуля участникам нужно перезагрузить клиент, чтобы они использовали одну версию протокола.

Расход патрона выполняется перед системным броском при подтверждении диалога. Две одновременно открытые атаки с последним патроном не создают два выстрела. Отмена диалога патрон не тратит. При ошибке выполнения до подтвержденной ChatMessage модуль пытается вернуть расход через ту же очередь. Разрыв соединения между сохранением и ответом остается неопределенным состоянием; это не серверная транзакция.

В режиме `perBullet` бросается число кубов, равное числу недостающих патронов. Если хотя бы один результат ≤2, ресурс уменьшается на одну ступень за действие — прежнее правило сохранено. MAG не запускает дополнительную системную проверку Arrows при выстреле. Для остальных видов оружия системная проверка сохранена.

## Что автоматизировано

Автоматизированы Надежное, Безотказное, Капризное, Утолщенное, Истонченное, Рисковое, Камора и Дозарядка. Остальные свойства и БП сохраняются как данные для ручных правил и интеграций; модуль не изменяет баланс, броню, дальность, действия или число выстрелов за игрока.

Расширенный конфигуратор открывается через `api.openFirearmConfig(item)`. Кнопки «Заполнить», «Очистить» и порядок свойств редактируют черновик и применяются вместе с «Сохранить», не расходуя ресурс. Если поле текущих патронов не редактировалось, сохранение конфигурации сохраняет актуальный боевой счетчик.
