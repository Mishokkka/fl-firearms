# FL Firearms 0.4.7: исправления и оценка CodeRabbit

Дата: 11 октября 2026. PR: https://github.com/Mishokkka/fl-firearms/pull/1. Основа проверки — версия 0.4.6, коммит `10e8b8e83415575f36b1a3aa613bfa890c25dcbf`. Целевая среда: Foundry VTT 13.351 / Forbidden Lands 13.0.5.

Исправления подготовлены для существующей ветки `initial-upload`. Приоритет — воспроизводимые ошибки дружеского стола, сохранение механики и надежная координация записей. Новые боевые правила и предложения по редизайну из первоначального аудита не добавлены в этот набор исправлений.

## Оценка CodeRabbit

Все шесть исходных замечаний по коду обоснованы. Однако это статический обзор: он не доказывает надежность сетевой игры и пропустил несколько наиболее значимых проблем контекста атаки.

| Замечание | Оценка и решение |
|---|---|
| Глобальная замена Arrows/Torches | Полезно. Ограничение целыми словами недостаточно: имя или заметка тоже может содержать отдельное слово. Замена теперь затрагивает только `.roll-consumable[data-consumable]`. |
| Tooltip считает отсутствующий magCurrent полным | Полезно. API использует `getMagazineCurrent()`, включая мировую настройку начального состояния. |
| ID конфигуратора основан только на Item ID | Полезно. Полный UUID кодируется без потерь в безопасный DOM ID. Embedded Items разных персонажей больше не сталкиваются. |
| Full Load / TopOff обходят lock | Существенная ошибка. Предложенная блокировка одного Item решает только часть проблемы: два оружия делят ресурс Actor, а два клиента имеют разные локальные Map. Реализована очередь на Actor у одного активного исполнителя. |
| Версия миграции повышается после ошибок | Существенная ошибка сохранности данных, а не только Minor. Проверяется фактическая нормализация всех запланированных документов; при частичном отказе версия остается прежней. В committable suggestion бота отсутствовал `+` перед суммой embedded изменений — предложенный фрагмент нельзя было копировать буквально. |
| Observer вызывает нормализацию при render | Полезно даже за доверенным столом: это ошибки прав, шум и неудачные обновления. Нормализация требует `isOwner`; контролы записи учитывают read-only. |

Замечание о слишком общем названии PR практично: описание должно объяснять изменения и проверку. Требование довести docstring coverage до 80% не является исправлением игрового бага и не использовано как критерий готовности. Для этого небольшого ES-module проекта полезнее документировать контракт очереди, ограничения сетевых отказов, правила ресурса и публичный API, чем механически комментировать 177 функций.

Автоматические release notes бота следует сверять с реализацией: наличие `lang/ru.json` не означает полную локализацию; имя журнала tooltip фиксировано, хотя имена таблиц и плейлиста настраиваются. README исправлен соответственно.

## Сетевые гарантии и пределы

Исполнитель выбирается детерминированным сравнением ID: активный GM, затем активный владелец, если GM отсутствует. Сравнение не зависит от локали браузера. Команды одного Actor UUID сериализованы; разные персонажи не блокируют друг друга. На собственном клиенте исполнителя используется прямой вызов без сокетного round trip.

Сокет использует штатный канал Foundry `module.fl-firearms`; в manifest включен `socket`. Дополнительный socketlib не нужен. Ответ привязан к инициатору, ID запроса и выбранному исполнителю. Временный кеш повторов ограничен по размеру/возрасту; незавершенные запросы не удаляются из него.

Если ответ не пришел за 30 секунд, локальный fallback и автоматический повтор не выполняются. Это существенно: запись могла уже пройти. Пользователь получает ошибку с просьбой проверить текущее состояние перед новым действием. При смене исполнителя еще не начатая команда завершается явным отказом, а новые команды используют нового исполнителя.

При неуспешной записи заряженного магазина модуль пытается восстановить ступень ресурса. При ошибке Roll до подтвержденного createChatMessage расход пытается вернуть через ту же очередь. Подтвержденный выстрел не возвращается из-за последующей ошибки обработки.

Эти механизмы не являются серверной транзакцией между Actor, Item и ChatMessage. Отключение исполнителя или потеря подтверждения посреди записи остаются неопределенным состоянием; автоматический повтор мог бы сделать его хуже. Дедупликация действует в течение жизни клиента/временного кеша, а не переживает полный перезапуск мира. В таких случаях нужен осмотр сохраненного состояния. Очередь не перехватывает прямые записи сторонних модулей и системный расход Arrows у обычных луков.

Авторизация команд не переработана в систему защиты от недоверенных игроков. Для указанного дружеского стола добавлены проверки корректности аргументов и владельца, необходимые для штатной работы, без дополнительных запросов подтверждения действий.

## Сохраненная механика и UX

- Профили d20/d10, Камора d12/d6, Безотказное и модификаторы таблицы сохраняются.
- В `perBullet` число кубов равно числу недостающих патронов; хотя бы один результат ≤2 уменьшает ресурс на одну ступень за действие. Правило не заменено последовательным уменьшением за каждый куб.
- Нулевой MAG capacity по-прежнему не является отслеживаемым магазином, но диагностируется как проблема настройки.
- Остальные свойства и БП остаются данными для ручных правил и интеграций. Новые эффекты дальности, скорострельности, брони, повреждения и действий не добавлены.
- Native Item Sheet и Quick Access сохраняют структуру и плоский API. Замены чата или нового интерфейса боя нет.
- Исправленный конфигуратор применяет draft через «Сохранить»; он не является боевой перезарядкой и не расходует ресурс.
- Повторные осечки используют числовую таблицу, не расходуя ее как колоду. Это явно закреплено в README.

## Выполненная проверка

Локально в Node.js 24.16.0 выполнены:

1. `npm run check`: синтаксис 27 JS/MJS файлов и корректность manifest, package и локализации JSON.
2. `npm test`: доменные правила, интеграционная симуляция и новый набор reliability.
3. `git diff --check`: проверка патча.

Новый набор проверяет параллельные Full Load/TopOff, общий ресурс двух разных оружий, отказ записи с компенсацией и освобождением очереди, отдельные экземпляры GM/игрока со stale replica, повторные пакеты, потерянный ответ без fallback, работу владельца без активного GM, последний патрон двух диалогов, Roll failure/refund и отказ после подтвержденной ChatMessage, отсутствие лишнего Arrows roll, parry, два unlinked NPC, отказ/повтор миграции, Observer, tooltip default empty, приватные карточки/таблицу, Push на неанглийской карточке, awaited delay и независимые окна/draft конфигуратора.

Проверка адаптера сверена с локальными исходниками установленной Forbidden Lands 13.0.5 и Foundry 13.351: `getRollOptions`, `executeRoll`, `handleRollArrows`, `pushRoll`, вызовы Hooks без await, `ChatMessage.applyRollMode` и `RollTable.toMessage`. Они служили источником контракта; файлы системы и Foundry не изменялись.

Это автоматизированная симуляция, а не тест настоящего socket.io сервера, DOM всех листов или двух живых браузеров. Foundry не слушал обычный локальный порт 30000 при проверке. Ручные сценарии для GM/игрока, задержек, смены GM и установленных расширений оставлены в `TEST-MATRIX.md`. Их нельзя считать выполненными на основании Node-тестов.

Предупреждения о намеренно сломанной записи миграции в логах reliability ожидаемы: тест проверяет сохранение старой версии и успешный повтор. Отсутствующий в fixture плейлист не является неудачей тестов.
